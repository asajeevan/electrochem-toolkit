# P08g: LANHE (LAND) `.cex` files, read natively

Status, 21 October 2026: **implemented and software-tested; verified on two real files (layouts `07 00 04 00` and `05 00 04 00`) by statements inside each file; neither file compared yet with LANHE's own Excel export.** Reader: `electrochem/readers/lanhe_cex.py` (`lanhe-cex` 1.1.0 from Cyclara 0.9.1; 1.0.0 in 0.9.0). Tests: `tests/test_readers_cex.py` (67 tests on synthetic files written by `tests/cex_synthetic.py`), `tests/test_interrupted_branches.py` (7 tests on hand-made tables), `tests/test_degenerate_pairs.py` (19 tests), and for the figures, views and peak tables of branches without a dQ/dE curve `tests/test_plateaus.py` and `tests/test_studio.py`. Deliberate faults: in 0.9.0, each of 28 put into the reader and 22 into the pairing rule, the figure fixes, the methods text and the app wording made a test fail; for 1.1.0 and the 0.9.1 engine changes, see section 8.4. The real files are a user's and private: they, their measurements and their protocols stay out of the repository, only how closely the checks agreed is quoted, and their regression checks live beside them.

## 1. Why a native reader

The `.cex` is the binary file LANHE's battery testers (sold by Wuhan LAND) write as a test runs. LANHE publishes no description of it. Cyclara 0.8.0 did not recognise it: the file reached the window as a raw `csv` error (0.9.0 refuses an unreadable binary in words). LANHE's Excel export is read by the `landt-xlsx` profile. A user's real `.cex` (private; rest, constant-current and constant-voltage steps) arrived on 20 October 2026, and the instruction was to read it in Cyclara directly; 0.9.0 does.

A second real file (private) arrived on 21 October 2026: layout `05 00 04 00`, with pauses, stops after which the tester restored an earlier state, and status events 0.9.0 had not seen. 0.9.0 refused it, as designed (a new layout). Reader 1.1.0 reads it; section 8 gives the evidence.

Sources. No published specification was found. One open project decodes the format for per-cycle capacities (`culture-medium/battery-data-tool`, `land_extract.py`, v0.5.7, inspected at commit 1037eb0): it carries no licence, so none of its code is used; its description of the header, the unit signatures and the 16-byte record helped locate fields, and every fact below was established again on the real files. That project reads capacity and energy only; it does not decode voltage, current or time, and it refuses the constant-voltage step type found here.

## 2. The format, as read

Little-endian throughout; offsets in bytes.

| Where | What | Status |
|---|---|---|
| header 0 to 3 | magic `10 11 09 88` | seen; checked on every file |
| header 4 to 7 | layout code `07 00 04 00` or `05 00 04 00` (16-byte records with float32 counters; the same units and records in both, each verified on a real file) | the two layouts read; others refused |
| header 16 to 19 | test start, Unix seconds (uint32) | equals the first step's start unit |
| header 24 to 27 | range codes (two uint16): voltage `0xE005`, current `0xC00A` | scales below; other codes see section 3 |
| header 28 to 31 | active mass, g (float32) | another project's reading; 0 in the first real file (not set), set in the second, not yet compared with the value entered in the tester's software; offered, never applied |
| units after the header | 16 bytes each, told apart by the first word | |
| `FFFFAAAA` ... `FFFFBBBB` | a block: type in the low 16 bits of word 1, payload length in the high 16, then the payload, then an end unit repeating words 1 to 3 | framing checked; types 0xAA, 0x55, 0x78, 0x13 (the step plan, written again when the plan is edited) and 0xCC (written at each pause) seen; skipped |
| `FFFFCCCC`/`FFFFCCCD`, kind 0x22 | step start: word 1 high 16 bits the tester's step number (bit 15 set); word 2 the step type (low byte), a flag byte, the setpoint in counts (high 16 bits); word 3 the start, Unix seconds | read |
| kind 0x44 | cycle marker: direction flag; the tester's cycle number (from 0) and step number | listed per step, not used |
| kind 0x33 | status event: word 2 the event code (low 16 bits) and a parameter (high 16 bits); word 3 a clock (Unix seconds) for most codes. Read: 0x0201 start, 0x0101 end and 0x0401 step change (listed, not checked), and the codes of section 8 (checked as section 8.2 says) | other codes refused |
| kind 0x88 | once, before the step plan | listed, not interpreted |
| kinds 0xB1, 0xB2 | retention references (another project's reading) | skipped with a note; not seen here |
| any other unit | data record: `uint32` time in 0.01 s since the test start; `int16` voltage counts; `int16` current counts (charge positive); `float32` capacity counter, Ah; `float32` energy counter, Wh | read |

Step types: `0x70` rest, `0x03` constant-current charge, `0x02` constant-current discharge, `0x05` constant-voltage charge. Any other type is refused, naming it.

Scales: full scale is reached at `0x7E00` = 32 256 counts. Voltage: 5 V / 32 256 per count. Current: 1 mA / 32 256 per count.

Counters: they restart at zero with each step, except that a step continuing the step before it in the same direction carries them on (the constant-voltage step after the constant-current one). A step's first increment includes the charge passed between the previous step's last record and its own first record (a fraction of a second), so the counter is the tester's charge, and the trapezoid of the logged current misses those short intervals.

## 3. Evidence for each fact, and the checks made on every file

Established on the first real file from four independent statements it makes in physical units, none of which the decoding assumed:

1. **Time unit.** The step-start units carry the tester's clock in whole seconds. The first record of every step follows its step's start by less than a second, over several hours: record time against clock time has a slope of 1 to within a few parts per million. A 0.01 s unit is the only one that fits.
2. **Current scale.** Over the intervals of each current-carrying step after its first, the trapezoid of the decoded current equals the increments of the float32 capacity counter (in Ah) to within 0.01 % on every step with 1 mA / 32 256 per count.
3. **Voltage scale.** On the same intervals, the trapezoid of decoded voltage times current, divided by the current's own ratio, reproduces the float32 energy counter (in Wh) to within 0.001 % with 5 V / 32 256 per count, over steps spanning very different voltages (so no offset).
4. **The step plan.** The plan block holds the programmed currents, voltage limits and setpoints as float32 (A and V). Under these scales the setpoint counts in the step-start units equal them to the rounding of one count, and every step ends where its programmed limit or duration says. This statement was used once, to establish the scales; it is not checked on each file.

The capacity counter could in principle be in mAh and the current scale a thousand times smaller; the programmed current in the plan (which would then have to be in mA too, an implausibly small current for a 1 mA channel), the range code and the other project's reading (verified there against LANHE's exports) all say Ah.

Each file opened is checked again on the first three statements, wherever it holds enough records for the check; when it does not, the import says so in a note (`cex_scale_not_checked`, `cex_voltage_not_checked`, `cex_clock_not_checked`) and the verified scales are used. The reader refuses rather than reads when a check fails:

| Check | Rule | Refusal code |
|---|---|---|
| clock | the clock time of each pause and stop (resume minus pause, or minus the moment restored) is added back for the step starts written after its resume; then the step starts are taken in consecutive intervals of at least 60 s of clock, and in each the record time must advance as the clock does, within 1 % plus 2 s (the clock reads whole seconds). Refused when fewer than half the intervals agree: a wrong unit fails every interval, a change of the clock or an unmarked pause only the one it falls in. Between consecutive step starts, a disagreement above 2 s plus 1e-4 of the time between them is warned with its place (`cex_clock_offset`). In reader 1.0.0 (Cyclara 0.9.0) the test was the least-squares slope over the whole test, which one change of the clock moves (section 8.3); the slope is still reported, for the drift | `cex_time_base` |
| current | trapezoid of the decoded current against the capacity counter, constant-current steps, intervals after each step's first, at least 20: within 0.2 % (1 % when only constant-voltage steps carry 20). Steps with a restart are left out (their record time goes back) | `cex_scale_check` |
| voltage | the same for voltage times current against the energy counter, normalised by the current's ratio, on at least 20 such intervals in steps whose voltage stays positive | `cex_scale_check` |
| direction | the net current of every step agrees with its step type | `sign_contradicts_step_type` |
| counters | both counters finite; the capacity counter never decreasing inside a step, except at a verified restart, and each step's starting at zero or carrying the step before it (anything else warned and read as a reset whose first increment is the counter's first value) | `cex_counter_decreases`, `cex_counter_invalid` |
| events | section 8.2: a pause or stop is ended by a resume with no record between; inside a step the records continue across a pause; a resume follows a pause or stop; resume details only at a resume; every other event of section 8 that lies inside a step sits where the records continue (time advancing by no more than twice the larger of the step's largest other interval and the typical interval of the file's steps of the same type, and the capacity counter not falling) | `cex_event_break` |
| restarts | section 8.2: the first record after a stop goes back by more than 0 s and at most 120 s of record time within the same step, its capacity and energy counters each between those of the two records around the moment restored; a stop resumed before the first record or after the last is refused | `cex_restart_unverified` |
| structure | blocks end where their length says; no unknown unit; no record before the first step start; time never decreasing, except at a verified restart | `cex_block`, `cex_unit`, `cex_records_before_step`, `cex_time_backwards` |

Not refused, and said: block types other than the five seen, and retention-reference units (kinds 0xB1, 0xB2), are skipped with a note. Range codes. `0xE005` (5 V) and `0xC00A` (1 mA) are verified. Another code of the same family is decoded by the family's rule (voltage `0xE0nn`: nn V; current `0xC0nn`: nn x 0.1 mA) **only when this file's own counters confirm the scale it gives** within the tolerance above, and the import says so (`cex_range_confirmed`); a file that carries too little current to confirm it is refused (`cex_range_unverified`). A code outside both families is refused.

## 4. What Cyclara does with it

The engine receives the same Table as from any reader: time (s), current (A, charge positive), voltage (V), the executed step number (1, 2, 3, ... in the order the steps ran, so every boundary shows even when a programme repeats a step), the mode (1 constant current, 2 constant voltage, 3 rest) and the charge increments from the counter. No native cycle number is passed: Cyclara pairs branches itself (M01 section 6), and the tester's cycle markers are listed per step. The tester's step table is rebuilt from the file and exported as `instrument_steps.csv` (step, tester's step number, type, setpoint, start on the tester's clock as Unix seconds and as a date and time, written without a time zone because the file records none, records, first and last time, voltage at both ends, how the counter started, counter values at the end, notes: pauses, restarts and events by step). `settings.json` carries the reader, its scales, every check, the pauses, the restarts and the other events under `import`.

Because the step types name the direction and the current's sign agrees on every step, the app answers "which current direction charges the cell" from the import and shows why; the configuration (cell voltage or half-cell) and the mass are still asked.

A restart (section 8) reaches the engine as time going back inside a branch: the interval across it is not integrated (M01 section 5.1), so the branch is partial, its cycle has no coulombic efficiency or retention, and the branch has no dQ/dE (M01 section 9.3); its capacity keeps every recorded increment, including the charge the tester's counter left out. When that cycle is the reference cycle, no cycle has a retention, and the summary and the methods paragraph say so; the summary asks for another reference. A pause reaches the engine as a marked row (`Table.paused`): the interval before it is integrated as usual, since the record time does not count the pause, so the branch stays complete with its efficiency and retention, but it has no dQ/dE, because the potential relaxes while the current is off (a precaution for pauses: M01 section 9.3). Either counts for the dQ/dE only between the branch's first and last row outside constant-voltage stages: a restart or pause inside a constant-voltage hold that ends a charge leaves its curve. Each cycle's note says which branch has no dQ/dE and why; the figures, the views and the peak tables leave such a branch out, and the summary names the cycles it leaves out.

## 5. Found while checking the outputs of the first real file

- **A step that ended at once.** One step of the file ended at its first check, after one recorded interval, with a negligible charge (as happens when a step to a voltage limit starts beyond that limit). Charge-first pairing put it with the full branch after it: a coulombic efficiency of millions of per cent. M01 section 6 now withholds the efficiency, the energy efficiency and the hysteresis of a pair in which one branch has at most two rows and under 0.1 % of the other's charge, and its retention too when that branch is the discharge; it keeps the capacities, energies and potentials of both branches and says why in the cycle's note. The app asks whether each cycle starts with a charge or a discharge when a file opens with such a branch.
- **The last branch.** The file's last branch reaches the end of the data, followed by the tester's end-of-test event. M01 treats a branch that reaches the end of the data as interrupted, so the cycle it belongs to has no coulombic efficiency in Cyclara. Whether the end-of-test event can be taken as "the run ended as programmed" is not established (a run stopped by hand may write the same event), so the rule is unchanged; the branch capacities are given.
- **Figures.** The dQ/dE map's two panels share a cycle axis, but each set it to its own cycles, so when the charge curves started a cycle later than the discharge curves the charge panel showed nothing; both now span the cycles of either. A single cycle was labelled 1.50, 1.75, ... in the map and the surfaces; now its own number. The summary figure's bin-width note could sit over a curve; it now takes a free corner or a band below the data. Figures and the app drew a hysteresis computed from the two averages even where the cycle's own value was withheld; they now draw the cycle's value.

## 6. Not verified, and what would verify it

- **LANHE's own export of either file.** Exporting a `.cex` from LANHE's software to Excel (its Record, Step and Cycle sheets) and comparing it row by row with Cyclara's reading is the independent check still missing. The internal statements above make a misread scale very unlikely; the export would also settle the tester's own cycle numbering, how it names the constant-voltage step, and how it shows the records a restart replays.
- **Never seen, so refused:** a stop whose records continue at a step boundary or in the next step, or that goes back 0 s; a stop resumed before the first record or after the last; an event of section 8 other than the resume details inside a step where the records break, for example between a stop's resume and the first record after it; a stop during a pause; other range codes without enough current to confirm them; other layouts (`01 00 04 00`, and `02 01 01 00` with counters instead of float32 values); constant-voltage discharge; temperature channels. Start, end and step-change events are listed wherever they are, without a check, as in 0.9.0.
- **Meanings not known:** of the events 0x1013, 0x0404, 0x2001 and 0x2004, of the words of the resume details, and of the parameter of a status event; each is read only as the records around it showed (section 8).
- **While the tester was stopped,** the file does not say what state the cell was in; a rest's duration in record time does not count the stop.
- **Files copied while the test was running** are read with a warning; synthetic only so far. A file that ends in a pause or a stop it does not show resumed is read with a note; synthetic only.
- **The active-mass field** has been seen set in one real file; it has not been compared with the value entered in the tester's software.

## 7. Refusal messages

Every refusal names what was found (the code, the offset, the record or the step). Those for a file this version cannot vouch for (another signature or layout, an unknown step type, status event or unit kind, a range code the counters cannot confirm, events out of the order verified or where the records break, a restart unlike the ones verified) also say to export the run to Excel from the tester's software, which Cyclara reads (`landt-xlsx`). The others (a damaged block or unit, records before the first step, an invalid or decreasing counter, time going backwards where no restart is marked, a time base or scale that fails its check, current against its step type) describe a file that is damaged or not what it claims, and give no remedy. A `.cex` refused for being new, sent with its Excel export, is the evidence the reader can be extended on. The Excel export checked (the Landt example of P08d) gives capacities and dQ/dE but, its time printed to 0.01 h, no efficiency or retention for any cycle today (an open question in M01 section 5.1), so it is a check of a reading rather than a substitute for it.

## 8. Reader 1.1.0: the second layout, pauses, stops and other events (21 October 2026)

### 8.1 What the second file showed

Each statement below was established on the second real file before the reader read it, from the records on both sides of every event and from the tester's clock:

1. **Layout `05 00 04 00`.** The units, the record and the scales are those of `07 00 04 00`: under the same scales the decoded current reproduces the capacity counter within 0.0002 % and the voltage the energy counter within 0.00001 % over the constant-current steps of the whole file, and the record time agrees with the step-start clock in every interval of the clock check once the pauses and stops are added back (over the whole test it runs about 1e-5 slower than the clock).
2. **Pause (0x0802) and resume (0x0203).** No record lies between them. The records on either side continue (the time advances by about one logging interval, the counters run on), and the step starts after the resume are later on the clock than the record time says by exactly the time from the pause event's clock to the resume event's clock, to the second: the record time does not count a pause. A block of type 0xCC follows each pause event. At each pause the first records after the resume lay a few millivolts nearer the rest potential than the last before it and returned within a few records: the cell relaxed while the current was off.
3. **Stop with a restored state (0x0803) and resume.** The first record after the resume is earlier in record time than the last record before it, by a few seconds; its capacity and energy counters lie between those of the two records around that earlier moment; and the step starts after it are later on the clock than the record time by exactly the resume event's clock minus the stop event's clock (word 3). So word 3 is the clock of the moment restored: the tester went back to its state of that moment and ran on from there. The records of those few seconds appear twice, and the counters of the second pass start again from the restored values, so the tester's own counter leaves out the charge passed in those seconds before the stop.
4. **Resume details (0x1008, 0x1012, 0x100E).** Every resume is followed by the three, and they occur nowhere else.
5. **Other events.** 0x1013 at regular intervals of the tester's clock; 0x0402 followed by a new step-plan block (hence its name); 0x0404, 0x2001 and 0x2004 a few times. At every occurrence the records continue as they did before it. Their meanings are not known.

### 8.2 What reader 1.1.0 does

- **Pauses** are read as they are. Inside a step the records must continue across a pause, as across any other event (below), or the file is refused (`cex_event_break`). A note lists the pauses (step, seconds on the clock) and says that a branch paused partway keeps its capacities and efficiency but has no dQ/dE; each step's notes name its pauses; the rows after them reach the engine as `Table.paused` (section 4); the clock check adds them back. A pause resumed before the first record or after the last is listed ("before the first record", "after the last record") and added back too.
- **Stops with a restored state.** Every record is kept, both passes of the replayed seconds included. The capacity increment of the first record after the resume is set to zero (the counter went back; that is not a charge), and the increments after it continue from the restored value, so Cyclara's charge for the step is the tester's final counter plus the charge the counter left out by going back. The record time goes back there, so the engine does not integrate the interval across the restart (section 4). The import warns at each restart (`cex_restart`) with the clock of the resume and of the moment restored, how far the record time went back, the records of those seconds, and the charge the counter left out (its drop at the restart); for a stop in a rest step it says that no charge is involved. A restart must go back by more than 0 s and at most 120 s of record time within one step, and the restored counters must lie between those of the two records around the moment restored (searched among the records since the step began, or since its last restart), or the file is refused (`cex_restart_unverified`); so is a stop resumed before the first record or after the last, which no records on both sides can check.
- **Event order.** A pause or stop must be ended by a resume with no record between them; a resume must follow a pause or stop; the resume details must sit where a resume is; a pause or stop with records after it and no resume is refused (`cex_event_break`). A file that ends in a pause or stop it does not show resumed is read, with a note (`cex_ends_paused`).
- **Other events** inside a step are checked at every occurrence: the time must advance across the event by no more than twice the larger of the step's largest other interval and the typical (median) interval of the file's steps of the same type (a step of two intervals, one a short last one, would otherwise allow almost nothing; the same type, because a file logs its rests and its current steps at different intervals), and the capacity counter must not fall, or the file is refused (`cex_event_break`). At a step boundary, or before the first record or after the last, they are listed only. A note counts them by place and code (`cex_other_events`; `other_events_where` in the report); each step's notes name the ones inside it, except the periodic event and the resume details.
- **The clock check** (section 3) adds back the clock time of every pause and verified restart, and judges the time unit interval by interval.
- **The scale check** leaves out steps with a restart.

### 8.3 Found while checking the second file's outputs, and by the review

- **False dQ/dE peaks at restarts.** Before the rule of M01 section 9.3, each branch with a restart showed a large false dQ/dE peak: the cell relaxed while the tester was stopped, the potential after the restart started again from a relaxed value, and the sorted Q(E) folded back on itself. A branch with a curve break (time going back or invalid, a missing current, an instrument error flag) now has no dQ/dE. The first form of the rule counted every unsupported interval; a census of the real files in `data/public` before the release showed that it would have removed every dQ/dE curve of the Landt Excel example, whose time is printed to 0.01 h so that most consecutive rows share a time. Zero-duration intervals lose no time and are not breaks.
- **Pauses fold the potential too.** The independent review pointed out that a pause stops the current as a stop does. At the pauses of the second file the potential relaxed by a few millivolts and returned within a few records; at the default 10 mV bin the dQ/dE of those branches did not differ visibly from the cycles on either side, but a pause has no bound on its length, and so on its relaxation. A branch paused partway therefore has no dQ/dE either; it keeps its capacities, completeness, efficiency and retention, since the pause neither loses time nor charge.
- **The summary named only an unfinished last cycle** as left out; interrupted cycles in the middle of a run were left out of its averages without being named. It now names them (the first twelve, and how many in all), and says when the reference cycle is not complete, so that no cycle has a retention.
- **The clock check's slope.** The least-squares slope over the whole test, the test of the time unit in reader 1.0.0 (Cyclara 0.9.0), would refuse a file with one change of the clock (a one-hour summer-time change in a one-day test moves it by 4 %). Found while writing the test of a pause the file does not mark, not in a real file. The unit is now judged interval by interval (section 3).
- **The review's other findings** (`docs/handoffs/Project_Status_Addendum_2026-10-21b.md` lists all 18 with what was done): a restart going back 0 s was accepted and then escaped the dQ/dE rule (refused now); a short step with one long and one short interval made a valid event look like a break (a typical logging interval is now part of the reference; the second review, below, made it that of the steps of the same type); pauses had no continuity check, and pauses or stops resumed before the first record or after the last were dropped silently (checked, listed or refused now); several messages and documents claimed more checking than the code did (reworded to what is checked where).
- **The second review** (a second agent, after the fixes; the addendum lists its eleven findings): the reference interval mixed the file's rests, logged every 60 s, with its current steps, logged every 10 s, so a short rest with an event was still refused, while a 90 s gap at an event in a current step was accepted in a file whose intervals are mostly those of its rests (now the typical interval of the steps of the same type); only the capacity counter was bracketed at a restart (now the energy counter too); a pause or restart inside a constant-voltage hold removed a dQ/dE curve it cannot fold (now only those between the curve's first and last row count); the export stopped with an error at the 3D figure when no branch had a curve, and a peak whose partner branch had no curve was reported as having no partner branch (each fixed, with tests); the methods paragraph gave every possible cause of a curve break rather than the actual ones and named an incomplete reference cycle as the retention's reference; and wording: "curve break" used for two things, the pause rule presented as established where it is a precaution, one Landt export generalised to all, and "until 1.0.0".
- **The third review** (a third agent, after those fixes; a build made from them was discarded): the methods paragraph no longer named an interruption inside a constant-voltage hold, which still leaves the cycle without efficiency; the restart warning and the pause note said the branch has no dQ/dE even in a hold; the dQ/dE view kept an earlier note above its "no curve" sentence; and wording ("first cycle only" when that cycle is not cycle 1, the cycle notes promised for every branch without a curve, "no dQ/dE" for every restart). Each is fixed, with tests; the addendum lists them.

### 8.4 Verification

- **Synthetic files.** `tests/cex_synthetic.py` writes either layout, pauses (also before a step's first record), stops with a restored state (one or several in a step), periodic events and any other unit between records, and gives, as part of the truth, the charge each restart's restored counter leaves out. `tests/test_readers_cex.py` (67 tests) checks that: layout 05 reads exactly as 07; pauses are read, the clock check counts them, the records are those of the same run without them, the paused branches have no dQ/dE while every cycle keeps its efficiency and retention, and the notes and the methods paragraph say so; only a pause inside a branch counts (one before a branch's first record does not, one before its last record does); a pause the file does not mark is warned, with its place, and a clock set back is called a change of the clock; periodic events change nothing; a restart keeps every record and the left-out charge (the branch capacity equals the constructed charge to 1e-6), makes its branch partial and its cycle without efficiency, gives that branch no dQ/dE, and, in the reference cycle, takes the retention from every cycle until another reference is chosen; two restarts in one step are each checked, including a second that restores a moment the first replayed; a restart in a rest is read and worded as such; restarts going back 0 s or over 120 s, a restored capacity or energy counter of another moment, records going forward after a stop (in a charge step and in a rest), a stop across two steps and a stop resumed after the last record are refused; events out of their verified order are refused (five cases), and so are an event or a pause where the records break (gaps of 210 s and 90 s in a step logged every 10 s, in a file whose rests are logged every 60 s) and an event where the counter falls; an event in a short step is judged by the typical interval of the file's steps of that type (a short discharge, and a short rest logged more slowly than the current steps); events at a step boundary are listed, not checked; a pause and a restart inside a constant-voltage hold leave the charge's dQ/dE, and the warning, the pause note and the methods paragraph say so (the paragraph still names the interval, which leaves the cycle without efficiency); the methods paragraph gives the reason when the reference cycle's discharge ended at once; an export in which no branch has a dQ/dE curve is written whole, each dQ/dE figure drawing the reason and passing every journal check;
